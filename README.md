## 🚨 The Problem

Organizations handling **highly sensitive data** — refineries, Public Sector Undertakings (PSUs), defense manufacturing units, and government offices — face a silent crisis:

| Challenge | Consequence |
|-----------|-------------|
| Cannot use cloud AI (Claude, ChatGPT, Gemini) — company policy forbids sending confidential data externally | Employees work **manually** → slow and inefficient |
| Employees secretly paste sensitive data into public AI tools | **Massive security breach** already happening quietly in many organizations |
| Existing on-prem AI solutions are research prototypes, not deployable products | No ready solution exists that "just works" |

**Engineering drawings. Financial records. Internal strategy. Defense blueprints.**
None of this can leave the building. Yet the productivity gap between AI-enabled and manual workflows grows every day.

---

## 💡 The Solution

**Singularity** is a **private, self-hosted AI agent platform** — a drop-in internal alternative to Claude or ChatGPT that runs *entirely* inside your organization's own servers with **zero internet dependency**.

It is not just a chatbot. It is an **agent**:

- 🧠 **Plans** multi-step work
- 🔧 **Uses tools** (code sandbox, file generation, document search)
- 📄 **Produces real deliverables** — DOCX, PPTX, PDF, working code
- 🔁 **Self-corrects** by iterating until output satisfies the request
- 🔒 **Logs every action** for full compliance audit trails

> Nothing typed into Singularity, uploaded to it, or generated by it ever leaves the building.

---

## ⏱ Why Now?

Three converging shifts make this the right moment:

1. **Open-weight models crossed the quality threshold.** The Qwen3 family, DeepSeek-R1-Distill, Mistral-Small, Gemma, and gpt-oss-20b now deliver capability that was GPT-4-class 18 months ago — and they run on modest hardware.
2. **Hardware is affordable.** Quantized models run on consumer GPUs. A self-hosted assistant no longer requires a data-center budget.
3. **No product exists yet.** There is a genuine gap between *"open models exist"* and *"industrial users can casually deploy an agent platform like they use ChatGPT."* Singularity fills that gap.

## 🏗 System Architecture

### High-Level Data Flow

```
┌──────────────────────────────────────────────────────────────────────┐
│                              USER                                    │
│                  (Browser on LAN / Wi-Fi Hotspot)                    │
└─────────────────────────────┬────────────────────────────────────────┘
                              │ HTTPS (local)
                              ▼
┌──────────────────────────────────────────────────────────────────────┐
│                     DJANGO BACKEND  (Control Hub)                    │
│  ┌────────────┐  ┌──────────────┐  ┌────────────┐  ┌─────────────┐   │
│  │ OpenLDAP   │→ │ Task         │→ │ Agent      │→ │ File        │   │
│  │ Auth       │  │ Classifier   │  │ Router     │  │ Generator   │   │
│  └────────────┘  └──────────────┘  └─────┬──────┘  └─────────────┘   │
└─────────────────────────────────────────┼────────────────────────────┘
                                          │  model-name routing
                                          ▼
┌──────────────────────────────────────────────────────────────────────┐
│                AI/ML LAYER  (Distributed Ollama Nodes)               │
│                                                                      │
│  ┌───────────────┐  ┌───────────────┐  ┌─────────────────────────┐   │
│  │ GPU Node A    │  │ GPU Node B    │  │ CPU Node                │   │
│  │ Reasoning /   │  │ Vision / OCR  │  │ Lightweight tasks       │   │
│  │ Coding models │  │ models        │  │ (embeddings, routing)   │   │
│  └───────────────┘  └───────────────┘  └─────────────────────────┘   │
└─────────────────────────────────────────┬────────────────────────────┘
                                          │
                                          ▼
┌──────────────────────────────────────────────────────────────────────┐
│                PLG OBSERVABILITY STACK                               │
│   Prometheus (metrics)  ·  Loki (logs)  ·  Grafana (dashboards)      │
└──────────────────────────────────────────────────────────────────────┘
```

### End-to-End Request Lifecycle

1. **Login** → User authenticates via **OpenLDAP** (enterprise-grade centralized identity).
2. **Prompt** → User submits text, image, or document.
3. **Classify** → Django backend determines the task type (code? summary? OCR? calculation?).
4. **Route** → The orchestrator selects the appropriate **specialized agent** → agent selects the **best-fit model**.
5. **Execute** → The model runs, optionally invoking tools (code sandbox, file generator, document search).
6. **Self-Check** → Output is evaluated against the original request; the agent iterates if needed.
7. **Deliver** → A real file is returned (DOCX / PPTX / PDF / code).
8. **Log** → Every step is streamed into the PLG stack for audit and monitoring.

## 🧠 The Multi-Agent Engine

Instead of forcing one general-purpose LLM to do everything, Singularity routes each request to a **specialized agent**:

| Agent | Purpose | Typical Models |
|-------|---------|----------------|
| 🧮 **Math Agent** | Symbolic and numeric computation | DeepSeek-R1-Distill, Qwen3-Math |
| 📐 **Drawing / Engineering Agent** | Reads technical diagrams, P&IDs, CAD exports | MiniCPM-V, Qwen-VL |
| 💻 **Coding Agent** | Writes, tests, and debugs code | Devstral, Qwen3-Coder, gpt-oss-20b |
| 🖼 **Multimedia / OCR Agent** | Scanned documents, handwriting, photos | PaddleOCR-VL, MiniCPM-V |
| 📝 **Document Agent** | Reports, summaries, approval notes | Mistral-Small, Gemma, Qwen3 |

A central **orchestrator** performs intent classification and dispatches to the correct agent. This is the direct technical answer to the core requirement:

> *"A coding request should be handled differently from a document summary request."*

### Model Inventory (12+ Open-Weight Models)

| Category | Models |
|----------|--------|
| **Reasoning** | DeepSeek-R1-Distill, Qwen3 (larger variants) |
| **Coding** | Devstral, Qwen3-Coder, gpt-oss-20b |
| **General / Chat** | Mistral-Small, Gemma, Qwen3 |
| **Vision / OCR** | PaddleOCR-VL, MiniCPM-V |
| **Multimodal** | Qwen3-VL family |

### The Self-Correction Loop

```
        ┌─────────────────────────────────────────┐
        │                                         │
   Prompt ──► Agent ──► Model Output ──► Evaluator │
                                │           │
                                │           ▼
                                │      Satisfied?
                                │       │     │
                                │      yes    no
                                │       │     │
                                │       ▼     └──► Refine ──┐
                                │   Deliver                │
                                │                          │
                                └──────────────────────────┘
```

This loop is what separates an **agent** from a simple chatbot and satisfies the explicit requirement to iterate *"until satisfied results are generated."*

## 👥 Three-Tier Role System

Singularity is designed to be **usable inside a real organization**, not just a tech demo.

### 🧑‍💼 User
- Logs in via OpenLDAP
- Prompts with text, images, and documents
- Generates and downloads files
- Manages personal chat history
- Provides feedback on outputs
- ⚠️ *Even "temporary" chats remain visible to managers* — essential for accountability in regulated industries

### 👔 Manager
- **Does not touch infrastructure** — governs people and policy
- Sets token quotas per role
- Authorizes / revokes access to specific models
- Reviews logs and flagged risky queries
- Receives **automatic email alerts** (via local mail server) when a malicious question is detected

### 🛡 Administrator
- Owns the infrastructure
- Adds / removes compute nodes (VMs)
- Manages model replicas for high availability
- Monitors raw resource usage
- Swaps models in or out
- Handles networking and local DNS

This mirrors how real enterprise software is organized — cleanly separating **who uses**, **who governs**, and **who runs**.

## 🖥 Physical Deployment

Singularity is designed to run on **realistic, modest hardware** — not a data-center.

### Reference Topology

| Node | Hardware | Role |
|------|----------|------|
| **GPU Node A** | i3 + 4 GB NVIDIA GPU | Runs Ollama (WSL2 / Ubuntu) → reasoning + coding models |
| **GPU Node B** | i3 + 4 GB NVIDIA GPU | Runs Ollama (WSL2 / Ubuntu) → vision + OCR models |
| **Control Hub** | i7 + 2 GB GPU + strong CPU | Django, OpenLDAP, PLG stack, **Wi-Fi hotspot** |
| **Client Node** | GPU-less laptop | Opens the web UI and displays the live Grafana dashboard |

### Software-Level Abstraction (No GPU Virtualization)

Rather than attempting the impossible task of merging consumer GPUs into one virtual device, Singularity abstracts at the **software layer**:

- Each model is exposed as an **API endpoint**
- Django routes by **model name**, not by physical machine
- The rest of the system neither knows nor cares which laptop is serving a given model

This is a genuinely reasonable way to demonstrate a **distributed, multi-node architecture** on hardware you actually have — exactly what the problem statement invites.

## 🏭 Production-Minded Design

Singularity is not a hackathon gimmick. Several design choices point directly toward real deployability:

- 🧩 **Modular model layer** — new open-weight models can be swapped in without redesigning the system. Critical, because this space moves fast.
- 🗂 **Full audit trail** — every conversation, including "temporary" ones, remains visible to managers. Satisfies compliance needs common in defense and energy sectors.
- 🔒 **Provable sovereignty** — the PLG stack doubles as a live network monitor demonstrating zero external calls.
- 📬 **Self-hosted alerting** — even malicious-query email alerts run on an internal mail server, so the *"nothing leaves the network"* claim holds end-to-end.
- 🔁 **Graceful degradation** — if a GPU node goes down, replicas on other nodes serve the same model name; the user sees no interruption.

## 🚀 Getting Started

> ⚠️ **Prerequisites:** Python 3.11+, Docker, Ollama, and at least one CUDA-capable GPU (optional but recommended).

### 1. Clone the repository

```bash
git clone https://github.com/your-org/singularity.git
cd singularity
```

### 2. Configure environment

```bash
cp .env.example .env
# Edit .env with your LDAP bind DN, model endpoints, and secret keys
```

### 3. Start the control hub

```bash
docker compose up -d django ldap prometheus loki grafana
```

### 4. Launch a model node

On each GPU node:

```bash
ollama serve
ollama pull qwen3:8b
ollama pull deepseek-r1-distill:7b
ollama pull paddleocr-vl
```

### 5. Register the node

```bash
python manage.py register_node --name gpu-node-a --endpoint http://192.168.1.10:11434
```

### 6. Access the platform

Open `http://<control-hub-ip>:8000` on any device connected to the local Wi-Fi hotspot.
