## 🚨 The Problem

Organizations handling **highly sensitive data** — refineries, Public Sector Undertakings (PSUs), defense manufacturing units, and government offices — face a silent crisis:

| Challenge | Consequence |
|-----------|-------------|
| Cannot use cloud AI (Claude, ChatGPT, Gemini) — policy forbids sending confidential data externally | Employees work **manually** → slow and inefficient |
| Employees secretly paste sensitive data into public AI tools | **Massive security breach** already happening quietly in many organizations |
| Existing on-prem AI solutions are research prototypes, not enterprise products | No deployable, governed, auditable solution exists |

**Engineering drawings. Financial records. Internal strategy. Defense blueprints.**
None of this can leave the building. Yet the productivity gap between AI-enabled and manual workflows grows every day.

---

## 💡 The Solution

**Singularity** is an **enterprise-grade, private, self-hosted AI agent platform** — a drop-in internal alternative to Claude or ChatGPT that runs *entirely* inside your organization's own infrastructure with **zero internet dependency**.

It is not just a chatbot. It is an **agent**:

- 🧠 **Plans** multi-step work
- 🔧 **Uses tools** (code sandbox, file generation, document search)
- 📄 **Produces real deliverables** — DOCX, PPTX, PDF, working code
- 🔁 **Self-corrects** by iterating until output satisfies the request
- 🔒 **Logs every action** for full compliance audit trails

> Nothing typed into Singularity, uploaded to it, or generated by it ever leaves the building — not even an email.

---

## ⏱ Why Now?

Three converging shifts make this the right moment:

1. **Open source models crossed the quality threshold.** The Qwen3 family, DeepSeek-R1-Distill, Mistral-Small, Gemma, Devstral, and gpt-oss-20b now deliver capability that was GPT-4-class 18 months ago — and they run on modest, on-premise hardware.
2. **Enterprise-grade self-hosting is affordable.** Quantized open source models run on consumer GPUs. A fully sovereign AI platform no longer requires a data-center budget.
3. **No enterprise product exists yet.** There is a genuine gap between *"open source models exist"* and *"regulated organizations can deploy a governed, auditable agent platform with a single internal API."* Singularity fills that gap.

### End-to-End Request Lifecycle

1. **Login** → User authenticates via **OpenLDAP** (enterprise-grade centralized identity — the *only* authentication path).
2. **Prompt** → User submits text, image, or document through the React frontend.
3. **Classify** → Django backend determines the task type (code? summary? OCR? calculation?).
4. **Route** → The orchestrator selects the appropriate **specialized agent**.
5. **Dispatch** → The request passes through the **Interface Layer**, which selects and calls the best-fit model for that domain.
6. **Execute** → The model runs, optionally invoking tools (code sandbox, file generator, document search).
7. **Self-Check** → Output is evaluated against the original request; the agent iterates if needed.
8. **Deliver** → A real file is returned (DOCX / PPTX / PDF / code).
9. **Log & Alert** → Every step is streamed into the PLG stack; any flagged query triggers a **docker-mailserver** email to the manager.

## 🧩 The Interface Layer

The Interface Layer is the architectural centerpiece that makes Singularity **enterprise-maintainable**.

### What It Does

- **Exposes a single, stable internal API** consumed by the Django backend — no application code ever talks to a model directly.
- **Routes by expertise** — the layer knows which model is best for coding, which for math, which for OCR, and dispatches accordingly.
- **Abstracts the hardware entirely** — the application layer never knows (or cares) which physical node serves a given model.
- **Handles failover and replication** — if a GPU node goes down, a replica on another node serves the same model name; the user sees no interruption.
- **Supports hot-swapping** — new open source models can be registered at runtime without redeploying the application.

### Why This Matters

> **Adding, removing, or upgrading a model is a configuration change — not a code change.**

This is the difference between a demo and a platform. Model landscapes move fast (new releases every few weeks). The Interface Layer ensures Singularity stays current without ever destabilizing the application.

## 🧠 The Multi-Agent Engine

Instead of forcing one general-purpose LLM to do everything, Singularity routes each request to a **domain-specialist agent**, backed by the **best-in-class open source model** for that domain:

| Agent | Purpose | Best-in-Domain Model |
|-------|---------|----------------------|
| 🧮 **Math Agent** | Symbolic and numeric computation | DeepSeek-R1-Distill |
| 📐 **Drawing / Engineering Agent** | Reads technical diagrams, P&IDs, CAD exports | MiniCPM-V / Qwen3-VL |
| 💻 **Coding Agent** | Writes, tests, and debugs code | Devstral / Qwen3-Coder |
| 🖼 **Multimedia / OCR Agent** | Scanned documents, handwriting, photos | PaddleOCR-VL |
| 📝 **Document Agent** | Reports, summaries, approval notes | Mistral-Small / Gemma |
| 🗣 **General Chat Agent** | Conversational reasoning and Q&A | Qwen3 (larger variants) |
| 🧠 **Reasoning Agent** | Multi-step planning and analysis | gpt-oss-20b |
| 🔎 **Retrieval / Embedding Agent** | Document search, semantic indexing | Dedicated embedding model |

A central **orchestrator** performs intent classification and dispatches to the correct agent. The Interface Layer then selects the best-fit model instance. This is the direct technical answer to the core requirement:

> *"A coding request should be handled differently from a document summary request."*

```
        ┌─────────────────────────────────────────┐
        │                                         │

                                     │             │
```

## 👥 Three-Tier Role System

Singularity is architected for **real enterprise governance**, not just a tech demo.

### 🧑‍💼 User
- Authenticates exclusively via **OpenLDAP**
- Prompts with text, images, and documents
- Generates and downloads files
- Manages personal chat history
- Provides feedback on outputs
- ⚠️ *Even "temporary" chats remain visible to managers* — essential for accountability in regulated industries

### 👔 Manager
- **Does not touch infrastructure** — governs people and policy
- Sets token quotas per role
- Authorizes / revokes access to specific models
- Reviews logs and flagged risky queries
- Receives **automatic email alerts via docker-mailserver** when a malicious question is detected

### 🛡 Administrator
- Owns the infrastructure
- Adds / removes compute nodes (VMs)
- Manages model replicas for high availability
- Monitors raw resource usage
- Swaps models in or out through the Interface Layer
- Manages OpenLDAP, docker-mailserver, networking, and local DNS

This mirrors how real enterprise software is organized — cleanly separating **who uses**, **who governs**, and **who runs**.

## 🖥 Physical Deployment

Singularity is designed to run on **realistic, modest on-premise hardware** — not a data center.

### Reference Topology

| Node | Hardware | Role |
|------|----------|------|
| **GPU Node A** | i3 + 4 GB NVIDIA GPU | Runs Ollama (WSL2 / Ubuntu) → reasoning + coding models |
| **GPU Node B** | i3 + 4 GB NVIDIA GPU | Runs Ollama (WSL2 / Ubuntu) → vision + OCR models |
| **Control Hub** | i7 + 2 GB GPU + strong CPU | Django, Interface Layer, OpenLDAP, docker-mailserver, PLG stack, **Wi-Fi hotspot** |
| **Client Node** | GPU-less laptop | Opens the React UI and displays the live Grafana dashboard |

### Software-Level Abstraction (No GPU Virtualization)

Rather than attempting the impossible task of merging consumer GPUs into one virtual device, Singularity abstracts at the **Interface Layer**:

- Each model is registered as an **API endpoint** behind the Interface Layer
- The application routes by **model name / expertise**, never by physical machine
- The rest of the system neither knows nor cares which laptop is serving a given model

This is a genuinely enterprise-reasonable way to demonstrate a **distributed, multi-node architecture** on hardware you actually have.

Singularity closes every privacy gap — not just the AI inference path.

| Channel | How It Stays Internal |
|---------|-----------------------|
| **AI inference** | All models run locally on-premise via Ollama |
| **Authentication** | All identity in **OpenLDAP** — no external IdP, no OAuth to the cloud |

## 🚀 Getting Started

> ⚠️ **Prerequisites:** Python 3.11+, Node.js 20+, Docker, Ollama, and at least one CUDA-capable GPU (optional but recommended).

### 1. Clone the repository

```bash
git clone https://github.com/your-org/singularity.git
cd singularity
```

### 2. Provision LDAP and Mailserver

```bash
cd infra
./setup-ldap.sh
./setup-mailserver.sh
```

These scripts configure OpenLDAP (base DN, OUs, role groups, service accounts) and docker-mailserver (SMTP/IMAP, DKIM/SPF/DMARC for the internal domain).

### 3. Configure environment

```bash
cp .env.example .env
# Edit .env with your LDAP bind DN, mailserver credentials,
# interface-layer endpoints, and Django secret keys
```

### 4. Start the control hub

```bash
docker compose up -d django interface-layer ldap mailserver prometheus loki grafana
```

### 5. Launch a model node

On each GPU node:

```bash
ollama serve
ollama pull qwen3:8b
ollama pull deepseek-r1-distill:7b
ollama pull devstral
ollama pull paddleocr-vl
```

### 6. Register models with the Interface Layer

```bash
python manage.py register_model \
  --name deepseek-r1-distill \
  --domain reasoning \
  --endpoint http://192.168.1.10:11434
```

### 7. Build and serve the React frontend

```bash
cd frontend
npm install
npm run build
```

### 8. Access the platform

Open `http://<control-hub-ip>:8000` on any device connected to the local Wi-Fi hotspot.
